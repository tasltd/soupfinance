SOUPFIN-146 — Backfill a chart of accounts for tenants with an empty one

Backend plan for soupmarkets-web, branch authentication-base-on-multi-tenancy-descriminator. Written 2026-10-12 from the SoupFinance repository, which may not change backend code (.claude/rules/backend-changes-workflow.md, SOUPFIN-13 directive). Builds on SOUPFIN-143 and SOUPFIN-145.

Goal. After one reviewed run, no non-archived SERVICES, TRADING or unclassified tenant has an empty chart of accounts. Each of them has the FINANCE module, which is what gates the Ledger and Accounting pages. Every tenant that already had accounts is byte-for-byte unchanged.

4. Rules the backfill enforces

  1. Empty means 0 LedgerAccount rows, archived included. Categories alone do not count: a tenant with the old categories and no accounts is seeded, and its categories are reused (matched case-insensitively), not duplicated.
  2. Which template. SERVICES gets services, TRADING gets trading, a null licence gets services. The licence is reported as licenceDefaulted, never written back. BROKER, ASSET_MANAGER, CUSTODIAN, TRUSTEE, PRIMARY_DEALER and FUND_MANAGER are skipped as no-template: they have their own brokerage chart.
  3. Country overlay when countryOfOrigin names one. The field is free text, so GH, gh, GHA, gha and Ghana all mean the Ghana overlay; anything else gets none. No industry overlay: there is no first-class industry field yet (parent plan, task 9).
  4. Archived tenants are skipped and do not count as still empty.
  5. One transaction per tenant, under Account.lock(id). The chart is written first, then the FINANCE module if no active one exists. A failure rolls that tenant back completely and the run carries on.
  6. Re-check under the lock. If the tenant gained an account between the scan and its transaction, it is skipped as gained-accounts and nothing is written.
  7. Tenants with accounts are not listed in the report, only counted (untouched). On TAS that is every brokerage tenant.
  8. A dry run is the default. A POST without dryRun=false writes nothing and returns what a real run would do, tenant by tenant. A check asserts the real run then does exactly that.

// CoaBackfillService
@WithoutTenant
Map run(boolean dryRun = true, List<String> accountIds = null) {
    // One query for the tenants that already have accounts, archived rows included.
    Set<String> nonEmpty = Tenants.withoutId {
        LedgerAccount.executeQuery('select distinct l.tenantId from LedgerAccount l') as Set
    }
    List<Account> tenants = Account.withCriteria {
        if (accountIds != null) {
            if (accountIds) inList('id', accountIds) else isNull('id')   // an empty list scans nothing
        }
        order('dateCreated', 'asc')
    }
    List<Map> rows = []
    int untouched = 0
    tenants.each { Account account ->
        if (account.id in nonEmpty) { untouched++; return }
        Map row = newRow(account)
        rows << row
        Map sel = selectionFor(account)                          // archived / no-template / template + overlays
        if (!sel.seed) { row.reason = sel.reason; return }
        try {
            Tenants.withId(account.id) {
                if (dryRun) { fillPreview(row, account, sel); return }
                LedgerAccount.withNewTransaction {
                    Account locked = Account.lock(account.id)
                    if (LedgerAccount.count() > 0) { row.outcome = 'skipped'; row.reason = 'gained-accounts'; return }
                    CoaApplyResult r = coaTemplateService.apply(locked,
                            new CoaApplyCommand(template: sel.template, overlays: sel.overlays, dryRun: false))
                    // Module last, in the same transaction: see finding 3.
                    if (!hasActiveFinanceModule(locked)) {
                        new AccountModule(account: locked, moduleGroup: ModuleGroup.FINANCE,
                                controller: ModuleGroup.FINANCE.controllerList, startDate: new Date()).save(failOnError: true)
                        row.moduleEnabled = true
                    }
                    fillResult(row, r)
                    row.outcome = 'seeded'
                }
            }
        } catch (Exception e) {
            log.error("COA backfill failed for ${account.id} (${account.name}): ${e.message}", e)
            io.sentry.Sentry.captureException(e)
            resetToFailed(row, e)
        }
        log.info("COA backfill ${dryRun ? 'dry run' : 'run'}: ${account.id} ${row.outcome} ${row.reason ?: ''} ${row.accountsCreated}")
    }
    return report(dryRun, tenants, untouched, rows)               // same keys as backfill.mjs
}
// AccountController
@WithoutTenant
def seedAllChartOfAccounts() {
    if (!SpringSecurityUtils.ifAllGranted("ROLE_ADMIN_ROOT")) {
        render status: 403, text: 'Admin root access required'
        return

               text: ([status: 422, code: 'invalid-dry-run', message: 'dryRun must be true or false'] as JSON).toString()
        return
    }
    List<String> ids = params.containsKey('accountIds') ? params.list('accountIds') : null
    render(coaBackfillService.run(dryRun, ids) as JSON)
}
// seedChartOfAccounts(id) is the same call with [params.id ?: Account.current().id].

Why not BootStrap. The existing module backfill runs on every boot (finding 5), and it would be the obvious home. But BootStrap runs on every server this WAR reaches, including brokerage production, on every deploy. Writing charts into production tenants should happen once, by a person who has read the dry-run report. The two admin actions give that; a boot hook does not.

Why one transaction per tenant, not one for the run. A single bad tenant would otherwise undo the other 206, and a run over hundreds of tenants would hold locks for minutes.
