SOUPFIN-151 — Account.industry as a first-class field

Backend plan for soupmarkets-web, branch authentication-base-on-multi-tenancy-descriminator. Written 2026-10-12 from the SoupFinance repository, which may not change backend code (.claude/rules/backend-changes-workflow.md). The frontend half (P1) ships with this plan.

Goal. A tenant's industry is stored on Account.industry as one of 16 fixed codes. Registration and account update accept it, account show returns it, and registration passes it to the chart-of-accounts composer whenever an overlay applies to the tenant's business type.

1. What was wrong

  • Registration never sent an industry. AccountRegistrationCommand has no such field, and AccountController.register builds the command field by field, so an extra key in the JSON is ignored.
  • The onboarding Company Information page put the industry label inside a JSON string called metadata on PUT /rest/corporate/update. Corporate has no metadata property, so the value was dropped silently.
  • Corporate.industry exists, but it is a ClientIndustry reference: a per-tenant lookup table for classifying KYC clients. A new tenant has no rows in it, and its names are free text, so it cannot pick a COA overlay. This plan leaves it alone.

4. Backend changes

P2 — Account.industry

// grails-app/domain/soupbroker/Account.groovy
/** Industry code (SOUPFIN-151). Picks the COA industry overlay when one applies. */
String industry

static final List<String> INDUSTRY_CODES = [
    'agriculture', 'construction', 'education', 'energy', 'financial-services', 'healthcare',
    'hospitality', 'manufacturing', 'mining', 'non-profit', 'professional-services', 'retail',
    'saas', 'telecommunications', 'transportation', 'other'].asImmutable()

// constraints
industry nullable: true, inList: INDUSTRY_CODES

Migration in lxc/migrations/: ALTER TABLE account ADD COLUMN industry VARCHAR(32) NULL;. No backfill: existing tenants stay NULL, which means "no overlay".

P3 — Registration

  • AccountRegistrationCommand: add String industry with industry nullable: true, inList: Account.INDUSTRY_CODES. An unknown code then returns the usual 422 with errors.industry, which RegistrationPage already renders per field.
  • AccountController.register: add industry: jsonData.industry to the command it builds.
  • AccountRegistrationService.register: set industry: cmd.industry on the new Account.
Found while tracing this. The same controller also ignores country, which the frontend has sent since registration gained the Country select. Account.countryOfOrigin stays empty, so the Ghana tax overlay cannot be chosen at registration either. Filed as SOUPFIN-240.

P4 — Show and update

  • _account.gson backfills keys the generic template drops when null. Add industry to that list, so /account/show/{id}.json always carries the key.
  • AccountController.update binds the domain from the request, so the new property binds once it exists. The frontend sends PUT /account/update/{id}.json with body {"id": "account-001", "industry": "saas"}, after reading CSRF from /account/edit/{id}.json.

P5 — Overlay at registration

Where registration seeds the chart (SOUPFIN-144), pass the overlay only when it applies, mirroring industryOverlayFor() on the frontend:

String overlay = coaTemplateService.industryAppliesTo(account.industry, account.businessLicenceCategory) ?
    account.industry : null
coaTemplateService.compose(account.businessLicenceCategory, country, overlay)

An industry with no overlay, or one that does not fit the business type (retail on SERVICES), seeds the base chart. Registration must not fail on it: the SOUPFIN-145 overlay-not-applicable error is for applyTemplate, where the user picked the overlay on purpose.

5. Frontend (done, P1)

  • Registration omits industry when none is chosen, so the backend never sees "".
  • Company Information writes only when the industry changed. It never sends industry to /rest/corporate/update, because that would try to bind a ClientIndustry reference.
  • Until P2 to P4 ship, the backend ignores the field: registration works, and /account/update answers 200 without storing it.

6. Template picker (P7, SOUPFIN-147)

The picker should call industryOverlayFor(account.industry, account.businessLicenceCategory) from src/utils/industry.ts and preselect the result. It returns null when no overlay applies, in which case the picker preselects none.

7. Related

  • Registration drops country (section 4, P3 note): filed as SOUPFIN-240.
  • plans/soupfin-146-coa-backfill.html skips the industry overlay because no field existed. Once P2 ships, a tenant that sets its industry later can add the overlay through SOUPFIN-145 applyTemplate.
