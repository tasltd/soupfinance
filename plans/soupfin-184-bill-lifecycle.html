SOUPFIN-184 — Bill lifecycle

Save draft, Submit, Void. Frontend shipped; backend actions planned for soupmarkets-web. Written 2026-10-14.

In short. The bill pages now follow the PRD lifecycle. The frontend is finished and tested. The backend has no draft, submit or void action yet, so on today's server those three buttons explain that nothing changed. This plan lists what soupmarkets-web must add for them to work.

1. What the backend does today

Checked on the LXC backend on 2026-10-14, and in soupbroker/finance/Bill.groovy.

  • Bill.status is a PaymentStatus. The backend derives it from payments in getCheckStatus() and marks it bindable:false, so a client cannot set it. The first 100 bills on LXC read: 66 null, 32 PENDING, 2 PARTIAL. index.json leaves out paid bills.
  • There is no draft or cancelled state. Every bill posts to the ledger when it is saved, through BillItemLedgerTransactionListenerService and TaxEntryBillItemLedgerTransactionListenerService.
  • OVERDUE is not stored anywhere. It means an unpaid balance past its due date.
  • POST /rest/bill/saveDraft.json, /submit/{id}.json and /cancel/{id}.json all return a Tomcat HTML 404 page.

2. The lifecycle

DRAFT ──Submit──▶ PENDING ──payment──▶ PARTIAL ──payment──▶ PAID │ (past due with a balance shows OVERDUE) └──Void (no payments)──▶ CANCELLED
ShownComes fromEditVoidPay
DRAFTpostingStatus = DRAFTYesNo (delete it instead)No
PENDING / PARTIALstatus (null is derived the backend's way)YesOnly with no paymentsYes
OVERDUEbalance > 0 and due date before todayYesOnly with no paymentsYes
PAIDstatus = PAIDNoNoNo

All of this lives in soupfinance-web/src/features/bills/billStatus.ts. Every page reads it, so the list, detail page, form, PDF and Pay Bills cannot disagree.

Migration: add the three columns; existing rows get POSTED (a null is also read as POSTED by the frontend). Add postingStatus, cancelledDate and cancelReason to _bill.gson and to the archived field list.

B2. POST /rest/bill/saveDraft.json

  • Same body and the same withForm CSRF token as save.json (token from create.json).
  • Sets postingStatus = DRAFT before billService.saveWithItems(...).
  • The two ledger listeners must skip any BillItem / TaxEntryBillItem whose bill is a DRAFT.
  • Responds 201 with the bill. It is a separate action on purpose: today's backend ignores unknown JSON properties, so a draft: true flag on save.json would silently post the "draft".

B3. POST /rest/bill/submit/{id}.json

  • No CSRF, like update. Empty JSON body.
  • Only from DRAFT, else 422 {"message": "Only a draft bill can be submitted."}.
  • Sets postingStatus = POSTED and creates the ledger entries the listeners would have made on save, dated the bill date. Respects the SOUPFIN-158 lock date (422 PERIOD_LOCKED).
  • Responds 200 with the bill (status then reads PENDING).

B4. POST /rest/bill/cancel/{id}.json

  • No CSRF. Body {"cancelReason": "optional text"}. The action is not called void because that is a reserved word for a Groovy method name.
  • Refuse with a JSON 422 {"message": …} when the bill is a DRAFT, already CANCELLED, PAID, or has any BillPayment. The frontend shows that message as is.
  • Reverse every LedgerTransaction for the bill's items and tax entries (contra entries dated today, or the first open date after the lock date). Do not delete them.
  • Set postingStatus = CANCELLED, cancelledDate = now, cancelReason. Respond 200 with the bill.

B5. Reporting and pickers

  • AP balance, aged payables and the dashboard "bills due" figures leave out DRAFT and CANCELLED bills.
  • Bill.searchList keeps drafts (the list shows them), but the bill payment pickers must not offer them. The frontend already filters them out of Pay Bills.
